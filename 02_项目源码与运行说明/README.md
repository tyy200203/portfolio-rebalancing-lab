# 组合实验室 · 投资组合分析与调仓模拟

单用户固定行情原型，完成“查看组合 → 集中度提醒 → 顺序调仓 → 前后对比 → 保存与重开”。所有核心计算、约束和持久化均在后端。数据为测评虚构数据。

本次提交为一个压缩包，分为 `01_开工方案与设计文档`、`02_项目源码与运行说明`、`03_验证记录与关键截图` 三个目录。解压后进入 **02_项目源码与运行说明** 再执行以下命令；设计与验证文档位于旁边的 01、03 目录。

## 环境与启动

- 实测 Windows、Node.js **v24.14.1**；推荐 Node.js 24 LTS。需要包含 `node:sqlite` 的官方 Node 发行版。
- 无第三方运行依赖、无需外部数据库、无需配置密钥。Node 24 可能打印 SQLite experimental warning，不影响本次运行。
- 在项目目录运行：

```sh
npm ci
npm start
```

浏览器访问 [http://127.0.0.1:3000](http://127.0.0.1:3000/)。第一次启动自动读取 `data/portfolio.json` 并创建 `storage/plans.sqlite`，不需要额外初始化。`npm ci` 安装浏览器测试开发依赖；如仅启动且无法联网，可直接 `npm start`。停止服务使用 Ctrl+C。

Windows PowerShell 若提示“无法加载 npm.ps1，因为在此系统上禁止运行脚本”，请改用 `npm.cmd ci`、`npm.cmd start`（测试同理使用 `npm.cmd test`），无需修改系统执行策略。启动后保持终端打开；服务停止或尚未重新启动时，浏览器可能显示 `ERR_CONNECTION_REFUSED`。重新运行启动命令，确认打印监听地址后再刷新页面。这两项均在候选人手动操作中实际遇到，并按上述方式恢复。

可选配置：`PORT` 指定端口，`DB_PATH` 指定 SQLite 文件绝对路径；默认仅监听本机。Windows PowerShell 示例：

```powershell
$env:PORT = '3001'
npm start
```

## 复现业务验收

1. 初始总资产 100,000.00、现金 20,000.00；星河科技 40%、科技行业 60% 触发提醒。
2. 卖出 A01 100 股：现金 30,000.00，两项提醒解除。
3. 再买入 A02 100 股：现金 25,000.00、A02 500 股、科技 55%，行业提醒出现。上方效果卡显示现金 +5,000.00、科技下降 5 个百分点、告警减少 1 项，并明确仍有 1 项超限。
4. 命名为“科技集中度部分降低方案”并保存。刷新后在右侧“已保存方案”点击名称；停止并重新启动服务，再次打开方案，结果相同。
5. 已保存方案为只读；点击“新建模拟”回到原始组合。原始现金始终 20,000.00、A01/A02 各 400 股。
6. 从新模拟买入 A01 201 股，查看现金不足错误。失败操作不会加入有效列表；零、负、小数在表单和后端均受校验。

刷新会丢弃**未保存**的模拟；已保存内容在 SQLite 文件内保留。允许同名方案，通过 UUID 区分；不实现编辑/删除。

页面内的“重试方案列表”仅刷新列表，保留已有草稿及模拟结果，与浏览器F5刷新不同。保存成功后若列表刷新失败，顶部仍显示保存成功，列表区域提示“方案已保存，列表刷新失败”；点击该重试按钮即可恢复列表，无需再次保存。

## 验证

```sh
npm test
npm run test:ui
```

`npm test` 使用 Node 内置测试框架，包含真实 HTTP 和服务进程重启。测试数据库在系统临时目录，与日常方案隔离。

浏览器测试使用 Playwright 和本机 Microsoft Edge；无 Edge 时运行 `npx playwright install chromium` 后设置 `BROWSER_CHANNEL=chromium`。测试默认 3107 端口，运行前确保未被占用。随包证据见 `../03_验证记录与关键截图/`；自行运行浏览器测试会在源码目录下生成新的 `screenshots/`。

## 项目结构

```text
src/domain.js       整数分计算、顺序执行、阈值与校验
src/server.js       HTTP 接口、静态页面、SQLite 持久化
public/            原生前端（只呈现后端计算结果）
data/portfolio.json 原始附件数据
tests/             计算、HTTP/重启、浏览器验收
```

开发工作区保留 PLAN.md、DESIGN.md、VERIFY.md 原件；提交包按三类归档，01 目录包含 PLAN.md / DESIGN.md，03 目录包含 VERIFY.md、日志与截图。

开发依赖及精确版本见 package.json / package-lock.json。交付不含 node_modules、个人简历、密钥或日常数据库；评审启动会创建自己的方案存储。详细边界与人工待验收项目见 DESIGN.md。
