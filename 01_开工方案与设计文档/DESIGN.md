# 投资组合分析与调仓模拟：设计与交付说明

任务依据：VC-FIN-001 / V3.0；交付日期：2026-11-09（北京时间）。开工原版见 PLAN.md。

## 1. 需求、范围与用户流程

目标是帮助用户识别当前持仓的集中度，并在固定行情下评估拟议买卖。FR-01～05 对应概览、集中度、顺序模拟、方案保存与重开、后端计算校验。核心验收条件是数字正确、状态隔离、操作失败不改变有效结果以及重启后恢复，并非功能数量。

页面将只读原始组合、模拟前后对比、操作工作台和已保存方案放在同一视图。初始展示原始现金/总资产/持仓市值/非零持仓标的数、每个标的价格/数量/市值/占比、行业分布和北京时间快照。所有告警写明对象、实际占比与阈值。

根据用户对首版的评阅意见，原始概览下新增“本次调仓效果”卡片，无需先浏览完整持仓表：AC-03 显示模拟现金 ¥25,000.00（+¥5,000.00）、科技 55.00%（下降 5.00 个百分点）、告警 1 项（减少 1 项），并提示仍有 1 项超限。示例名改为“科技集中度部分降低方案”，避免把“降低”误读为“已经解除”。突出行业固定选择原组合市值最大的行业，本数据为科技，不随模拟结果切换比较对象。

### 范围如何确定

先将任务书映射为一个可验收闭环，再按“是否阻断核心验收”决定投入：

| 工作 | 范围判断 | 理由与验证证据 |
|---|---|---|
| 后端精确计算、顺序约束、失败隔离 | 必须完成 | 直接决定 AC-01～04；以独立金额常量和边界断言核验。 |
| 保存独立快照、重启重开 | 必须完成 | 缺少它无法完成 AC-05；真实子进程重启测试验证。 |
| 效果摘要、剩余超限提示、故障回归 | 本轮补强 | 用户评阅指出业务效果不够直观、失败证据不够强；不改变业务范围，补充展示与验证。 |
| 登录、实时股价、复杂策略、收益预测 | 不实现 | 任务书排除或不要求；会引入认证、行情时效和策略正确性等额外问题，无法增强固定快照验收。 |
| 更换前端/后端框架 | 不实施 | 现有架构足以支持单页面与 100 笔模拟，重构不能弥补人工复核证据。 |

本轮用户明确要求保留轻量架构、加强证据并调整交付结构。这是已发生的需求评阅输入；不把它扩写成候选人已经阅读代码或亲自执行测试的证明。

用户逐笔选标的、方向和正整数数量，点击添加；后端接受整段候选操作序列并重放。只有成功响应才替换前端有效状态。错误反馈展示失败的第几笔及原因，保留之前的有效序列和结果。支持撤销末笔、新建模拟。保存时输入名称，保存后只读；重开时展示同样的前后对比和操作列表。

组合初始化和方案列表加载分别处理：组合尚未成功加载时，提供“重试加载组合”；组合有效而列表失败时，在列表区域显示失败提示和“重试方案列表”，只发送 GET /api/plans，不重新初始化组合、不改变操作序列和模拟结果。零操作时显示引导，允许保存为基准方案；列表查询成功且为空时才显示“暂无方案”。请求期间禁用操作按钮，避免同一页面并发提交。移动端变为单列，表格可横向滚动。

保存和刷新列表是两个独立请求：POST /api/plans 成功后立即确认保存并进入只读状态；后续 GET /api/plans 失败只在列表区域提示“方案已保存，列表刷新失败”，保留顶部成功反馈，提供只刷新列表的入口，不重新提交保存。若此前是空列表，失败后改为“当前无法获取最新方案列表”；若已有条目则保留并提示列表未刷新。模拟/保存请求本身失败时维持此前有效状态，列表故障与交易故障分别反馈。

边界：单用户、单币种 CNY、固定价格、无手续费/税费/卖空/融资。无登录、行情接口、收益预测或真实交易。持仓数指非零持仓标的数；清仓后仍保留标的行以便买回。模拟最多 100 笔，HTTP 请求体最多 64 KB；名称去空格后 1–60 个 Unicode 字符，允许重名。未保存草稿不恢复。

## 2. 系统结构与数据关系

```text
浏览器 HTML/CSS/JS
  ├─ GET 原始组合 / 方案列表 / 方案详情
  └─ POST 候选操作序列 / 命名方案
             ↓
Node.js HTTP（结构校验、错误封装）
             ↓
domain.analyze（快照拷贝 → 逐笔校验与执行 → 汇总集中度）
             ↓
SQLite（独立快照 + 操作序列 + 计算版本）
```

原始 JSON 定义组合 ID、币种、快照 ID/时间、现金、标的（代码/名称/行业/价格/数量）和规则。原始快照在服务启动时读入并校验，模拟仅操作局部拷贝。浏览器和请求均不能修改服务器基准数据或规则。

方案表 `plans`：`id TEXT PRIMARY KEY`（UUID）、`name TEXT`、`created_at TEXT`（UTC ISO）、`snapshot TEXT`（完整 JSON）、`operations TEXT`（有序 JSON）、`calculation_version INTEGER`（当前 1）。一条 INSERT 原子写入完整方案，SQLite WAL 保障提交持久性。SQL 使用参数绑定；前端动态文本进行转义，避免方案名或数据成为 HTML。

重开不读取当前组合替代历史快照，而是读取方案中保存的独立快照，调用相同计算函数重新生成原始/模拟结果。结果不持久化，避免结果字段与操作序列失配；版本不支持时拒绝重算。列表按时间倒序，无分页（测评单用户规模）。保存接口也重新校验，不能绕过试算提交非法操作。

## 3. 接口契约

| 方法/路径 | 输入 | 成功输出 |
|---|---|---|
| GET /api/portfolio | 无 | 快照元数据、original、simulated（与原始相同）、空 operations |
| POST /api/simulate | `{operations:[{symbol,side,quantity}]}` | 快照元数据、原始与模拟汇总、操作序列 |
| POST /api/plans | `{name,operations}` | 201，重算结果及 id/name/createdAt |
| GET /api/plans | 无 | id/name/createdAt 列表 |
| GET /api/plans/:id | UUID | 保存快照重算结果及方案信息 |

side 为 `buy`/`sell`，quantity 必须是 JSON number 类型的安全正整数，不接受字符串。金额响应为两位小数字符串；weight 为百分数的两位小数字符串（如 `40.00` 代表 40%）。汇总包含 total/cash/invested/cashWeight/holdingCount/positions/industries/alerts。

组合/模拟/方案详情响应另含 `impact`：cashDelta（有符号金额字符串）、industry、industryWeight、industryDeltaPoints（有符号百分点字符串）、alertCount、alertDelta。变化值也由后端生成；行业百分点变化是前后两位小数展示占比之差，仅用于展示，精确阈值判定仍独立进行。

错误格式：`{error:{code,message,operationIndex?}}`。operationIndex 为从 0 开始的失败操作位置，界面转为第 1 笔等自然序号。400 表示非法 JSON/参数/交易约束，413 表示体积超限，404 表示不存在的资源，500 表示内部/数据库异常（前端仅显示通用消息，服务日志记录详情）。模拟失败不保存任何结果；保存失败不创建方案。

## 4. 金额、阈值与异常处理

从十进制字符串解析为 BigInt 整数分，例如 `100.00 → 10000n`。市值=价格分×数量；总资产=现金分+市值分之和。每一笔买入先检查现金足够，卖出先检查当前模拟持仓足够，然后修改局部状态。任一步抛错则整次请求不给出新有效结果。固定价格无费用，每笔现金变化与持仓市值变化相反，因此总资产守恒。

占比展示由整数分子/分母四舍五入到百分数两位小数。判定单标的超限使用 `value*100 > total*30`，行业使用 `value*100 > total*50`，不使用展示值判断。现金计入总资产，不计入行业。零总资产时占比定义为 0（防御性处理，本例总资产不为零）。数量限制为 JS 安全整数，现金/市值乘法使用 BigInt，不受 Number 货币浮点误差影响。

启动即校验价格格式/正数、持仓非负安全整数、标的唯一、资料完整以及任务规则。缺失价格不按零估值，应拒绝计算并要求补全快照；若扩展至真实数据，未知行业可归为“未分类”并明确提示，当前输入缺失行业时拒绝启动，防止默默漏算。非法存储内容和磁盘问题返回失败，不能声称保存成功。

## 5. 关键决策与备选方案

| 决策 | 备选 | 采用理由与代价 |
|---|---|---|
| Node.js 24 内置 HTTP + 原生前端 | FastAPI/Vue、Express/React | 单页面核心流程无需框架；本机已有 Node，可直接运行，减少依赖。候选人简历偏 Python，但本次以交付可复现和业务规则透明为优先；代价是表单状态需手动管理，若多人开发会迁移组件框架。 |
| 内置 SQLite | JSON 文件、PostgreSQL | JSON 易实现但读改写冲突与半写入恢复需自建；SQLite 提供单条写入原子性且无需数据库服务。代价为 Node 版本要求和实验性 API 提示，未验证多进程高负载。 |
| 快照+操作持久化，结果重算 | 保存结果 JSON、只保存快照 ID | 完整快照保证历史解释，统一函数避免两套口径；版本字段为未来迁移留依据。代价是每个方案重复少量快照数据、重开需重算。 |
| 每次发送完整操作序列 | 服务器有状态模拟会话 | 失败天然不修改已有方案，易测试与复现；代价是随操作数线性重放，100 笔上限足够本次范围。 |

### 三项决策的推导与核验依据

以下为依据已有实现、真实测试和本轮评阅整理的决策说明，不伪造实现前的候选人思考过程；实现前原版仍为 PLAN.md。

**决策 A：BigInt 整数分。** 问题：需要精确判断阈值且固定价格交易不能产生货币尾差。候选方案是 Number 元金额、Number 整数分、BigInt 整数分或十进制定点库。Number 元金额可表达当前整元样例，但并不保证小数价格运算精确；Number 整数分在安全整数范围内也可行，需额外限制金额乘积。选择 BigInt 整数分，是为了以较少代码获得精确乘法和阈值交叉相乘，无需新增运行依赖。验证：新增 0.30 元买 3 股 0.10 元，现金必须严格为 0.00；金额超过 Number 安全整数的分值时，扣除 0.10 元后仍精确；30%/50% 两个阈值各覆盖等于、略高、略低。剩余风险：只支持两位小数 CNY，不覆盖汇率/手续费及四位报价；BigInt 不能直接 JSON 序列化，因此接口统一输出字符串。

**决策 B：完整操作序列重放。** 问题：第 N 笔无效时，不能破坏前 N−1 笔有效状态或原组合。候选方案是每笔修改数据库持仓（需事务/回滚和会话隔离）、服务器维护临时模拟会话、每次从不可变快照重放完整序列。选择重放，是因为只有单用户和最多 100 笔，不需要为草稿引入数据库状态；一次请求内的局部对象被丢弃即可实现失败隔离。验证：先卖再买与逆序结果不同；后续超卖不改变先前有效结果；浏览器分别验证业务 400、模拟 500、网络中断、保存 500 后，操作列表、现金、对比表与效果卡都保持不变。剩余风险：每次计算随序列长度增长；未保存草稿刷新会丢失；跨设备协作会需要新架构。模拟阶段不写数据库，只有最终命名保存时写入完整方案。

**决策 C：保存快照与操作，不只保存最终结果。** 问题：评审重开时不仅要看到数字，还要解释这些数字基于哪份行情、经过哪些买卖。候选方案是只存结果、只存快照 ID+操作、保存完整快照+操作。只存结果无法重放核验；只存快照 ID 依赖外部历史行情始终可取。选择完整快照+操作，重开调用同一计算函数，附计算版本号避免将未来算法静默应用于旧方案。验证：真实 HTTP 保存、关闭服务进程、启动后重开，整个详情与保存响应一致；原始组合仍为现金 20000、A01/A02 各 400；非法方案和 SQLite INSERT 注入失败均不增加记录数。剩余风险：快照有冗余，未来算法升级需迁移策略；当前尚未自动覆盖“替换数据文件后再重开”的场景，不能把重启测试等同于该项覆盖；只存结果有利于审计冻结，但需要额外维护一致性，本范围暂不采用。

## 6. AI 协作记录与实际核验

本项目使用 Codex 辅助开发。我主要承担实现范围确认、业务结果复算、人工流程验收、问题反馈及交付材料核对；Codex 承担方案草稿、代码生成、自动化测试执行和文档整理。

### 我的主要工作与判断

**确定实现范围。** 我围绕“组合查看—集中度识别—顺序调仓—保存与重开”确定核心交付闭环，要求优先保证计算正确、失败状态保留和重启恢复。结合测评建议投入，保留 Node.js 原生 HTTP、SQLite 和原生前端方案，将工作集中在核心流程及验证证据上。

**复算关键业务结果。** 我亲自复算了初始总资产100,000元、科技行业占比60%；卖出A01 100股后，现金为30,000元、科技占比为50%；再买入A02 100股后，现金为25,000元、科技占比为55%。通过这些固定算例核对页面结果，并验证“恰好等于阈值不告警”的业务口径。

**执行人工流程验收。** 我在本地完成启动、连续调仓、现金不足错误反馈、方案保存与重开、服务重启恢复及原始组合隔离检查，保留了操作截图。本轮人工操作检查约20分钟。过程中遇到 PowerShell 执行策略限制及服务停止后的连接失败，按指引恢复后，要求将处理方式补充到运行说明。

**发现并推动修复故障恢复问题。** 在后续复核中，我提出了两个具体场景：

- 组合加载成功而方案列表失败时，完整初始化重试会清空已有模拟草稿。我要求将组合初始化与列表重试分开，并验证重试前后的操作数、现金和对比结果保持不变。
- 保存成功后列表刷新失败时，错误提示会覆盖成功反馈。我要求分别处理保存与列表查询，保留保存成功状态，提供只刷新列表的入口，并检查重试不会重复创建方案。

这两项修改由 Codex 实现并执行浏览器回归。验证不仅检查页面提示，还核对了请求次数、数据库记录数量及有效模拟状态，具体结果见 VERIFY.md。

**核对交付证据。** 我指出两张人工重开截图内容相同，要求明确标注同图复用。最终材料将人工操作确认、截图展示和自动进程重启测试分别说明，避免重复计算证据。具体哈希与证据边界见 VERIFY.md 和 screenshots/manual/EVIDENCE.md。
